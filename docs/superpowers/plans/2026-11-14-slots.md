# Slots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/slots` page with three classic three-reel machines that take an offline character's money, a GM page for the switches and stake sizes, and "Slots" in the "Try Your Luck" menu.

**Architecture:** Machines (reel strips, payout tables) are fixed data in `packages/shared`, with a function that counts every possible result so each machine's return is exact and tested. The API draws three stops, reads the prize and moves the money with roulette's existing `walletBetSql` batch. The page draws the reels from a pure motion function, like the roulette wheel.

**Tech Stack:** NestJS + mssql + zod (API), React 19 + TanStack Router/Query + Tailwind (web), vitest, SQL Server.

**Spec:** `docs/superpowers/specs/2026-11-14-slots-design.md`. Read it first. This feature is built on roulette: `docs/superpowers/specs/2026-11-14-roulette-design.md`, `apps/api/src/roulette/`, `apps/api/src/games/wallet-bet.ts`, `packages/shared/src/roulette.ts` and `games.ts`, `apps/web/src/routes/_authed/roulette.tsx`, `apps/web/src/lib/roulette.ts`, `apps/web/src/components/roulette/` and `components/games/`, and their tests. Copy roulette's patterns unless this plan says otherwise.

## Global Constraints

- **Never edit or print `.env`.** It names the live databases. Run DB tests with `DB_GLOBAL_NAME=TGLOBAL_GSP_TEST DB_GAME_NAME=TGAME_GSP_TEST` set in the shell. A worktree has no `.env`: load the main one into the shell first, then set those two names.
- **Never run SQL against `TGAME_GSP` or `TGLOBAL_GSP`.** Only the `_TEST` copies, and DB tests roll everything back.
- **No dev servers, no browsers, no screenshots, no `nest build`.** Vitest only, affected files only, with `--maxWorkers=2`.
- **Run every test command from a folder spelled with a capital `C:`** (`cd "C:/Users/..."`). From a lowercase `c:` folder vitest fails every file with "failed to find the current suite".
- `@4story-portal/shared` is consumed from `dist`: after changing it run `npm run build -w packages/shared` before API or web tests.
- Money on the wire: stakes and payouts are whole **Silver** (1 Gold = 1000 Silver); a wallet is `{ gold, silver, copper }`. In the database, stake, payout and wallet-after are **Bronze** in `BIGINT`; the mssql driver returns `BIGINT` as a string, so convert with `Number()`.
- Three reels of 32 stops, one win line (the middle row), counted from the left reel: three of the same symbol pays that symbol's prize; two of the machine's lucky symbol (its first) pays the small prize. A prize is a multiple of the stake, stake included. A spin pays at most one prize, the highest that applies. Every stop is equally likely.
- A stake is 1 Silver to 100 Gold (100 000 Silver); a machine's three stakes are different, lowest first.
- The floor starts closed. Missing setting rows mean: floor closed, every machine open, starting stakes. Nobody spins while the floor or the machine is closed, GMs included.
- Roulette must keep working exactly as it does: its tests pass unchanged except for setup lines a refactor in this plan forces.
- The game calls the coins Gold, Silver and Bronze in everything a person reads. Code and columns keep `copper` / `dwCooper`.
- UI copy is plain ASCII punctuation, sentence case, no exclamation marks. Exact strings in this plan are verbatim.
- Commits: `feat:` / `fix:` / `test:` / `docs:` prefix, ending with the `Co-Authored-By:` line the committing session is given. Work on branch `feat/slots`, never on `main`.

## Review Focus

1. **Spin pressed twice, the space bar held down, or space pressed while typing in a field:** one press sends one spin; a held key does not repeat; space in the character picker or any input does nothing to the reels. (Task 5)
2. **A GM changes a machine's stakes or closes it while a player is on it:** the spin is refused with the reason, nothing is taken, the page shows the new stakes, and the chosen stake falls back to one that exists. (Tasks 3 and 5)
3. **The player switches machine while the reels turn:** the machine tabs are disabled until the last reel stops, so a result never lands on another machine's reels. (Task 5)
4. **A remembered machine or stake that no longer exists** (old browser storage, a machine removed later): the page falls back to the first machine and its lowest stake instead of breaking. (Task 5)
5. **History rows or setting rows that no longer fit** (a spin row for a machine not in the code, stakes text like `abc`, `50,10,25` or `10,10,25`): lists skip the unknown row; unreadable stakes fall back to the starting ones. (Tasks 2 and 3)

export function reelStop(position: number): number;
