# GM Events Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GM page to create, edit and stop EXP, drop and other percentage events through `TControlSvr`, the way Happy does.

**Architecture:** `control-protocol.ts` learns the event messages and `ControlClient` learns to wait for a reply, one request at a time. `EventsService` turns form input into wire events, applying the rules from section 2.6 of the spec. `/gm/events` is a list with a create and edit form, sharing a Zod schema with the API.

**Tech Stack:** NestJS 12, Zod 4, React 19, TanStack Router and Query, react-hook-form, Tailwind, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-01-gm-events-design.md`. Read it first; section 2 explains why the rules below exist.

## Global Constraints

- Work in `.worktrees/gm-events` on `feat/gm-events`. The worktree has no `.env`, and nothing here runs against a real database or control server.
- Never send requests to ports 3000 or 5173, and never log in as `portal` to the real control server: the user's dev API holds that session against live.
- No server, database or client changes. The game source is read only.
- Commit messages follow the repo style (`feat(api): …`, `feat(web): …`) and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- API code style: 2 spaces, semicolons, `.js` import suffixes. Web code style: no semicolons, single quotes, no import suffixes.
- The apps import `@4story-portal/shared` from its `dist`. After changing it, run `npm run build -w packages/shared` before running API or web tests directly.

## Review Focus

1. **Text the protocol can't carry (Greek, emoji) in a title or message:** a field error, never garbled bytes. Test in Task 1.
2. **A daily window crossing midnight, and an end notice as long as the event:** a field error, never an event that silently doesn't run or announces its end at the start. Test in Task 1.
3. **A route index that is non-numeric, 0 or above 2147483647:** a 400, never a 500. Test in Task 4.
4. **The control server dropping while a request waits or is queued:** a 503 straight away, never a hang until the timeout. Test in Task 3.
5. **An event ending while its edit form is open:** the 404 message appears in the form, and the list refreshes. Test in Task 6.
