# Roulette Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `/roulette` page where a player stakes an offline character's money on a European roulette table, with a GM page for the switch and limits, under a new "Try Your Luck" menu group.

**Architecture:** The rules (spots, payouts, pocket order, bet checks) live in `packages/shared` so the page and the API agree. The API draws the pocket and runs the whole bet as one SQL batch built from its configured table names: it locks the account's rows in the online list, checks the character and wallet, updates the wallet and inserts the spin row. The page draws an SVG wheel driven by a pure `frameAt(plan, seconds)` function and a betting table of buttons.

**Tech Stack:** NestJS + mssql + zod (API), React 19 + TanStack Router/Query + Tailwind (web), vitest everywhere, SQL Server.

**Spec:** `docs/superpowers/specs/2026-11-14-roulette-design.md`. Read it first. The closest existing feature is the Wheel of Fortune (`apps/api/src/wheel/`, `apps/web/src/routes/_authed/wheel.tsx`, `apps/api/test/wheel.http.test.ts`, `apps/api/test/db/wheel.db.test.ts`, `apps/web/src/routes/wheel.test.tsx`); copy its patterns unless this plan says otherwise.

## Global Constraints

- **Never edit `.env`.** It names the live databases. Run DB tests with `DB_GLOBAL_NAME=TGLOBAL_GSP_TEST DB_GAME_NAME=TGAME_GSP_TEST` set in the shell. A worktree under `.worktrees/` has no `.env`: load the main one into the shell first, then set those two names.
- **Never run SQL against `TGAME_GSP` or `TGLOBAL_GSP`.** Only the `_TEST` copies, and DB tests roll everything back.
- **No dev servers, no browsers, no screenshots, no `nest build`** on this machine. Vitest only, affected files only, with `--maxWorkers=2`.
- `@4story-portal/shared` is consumed from `dist`: after changing it run `npm run build -w packages/shared` before API or web tests.
- Money on the wire: bets, limits, stake and payout are whole **Silver** (1 Gold = 1000 Silver); a wallet is `{ gold, silver, copper }`. In the database, stake, payout and wallet-after are **Bronze** in `BIGINT` (1 Silver = 1000 Bronze). The mssql driver returns `BIGINT` as a string: convert with `Number()`.
- Bets: a number pays 35 to 1; red, black, odd, even, 1 to 18, 19 to 36 pay 1 to 1; dozens and columns pay 2 to 1. Zero wins only for a chip on 0.
- Limits start at: smallest bet 10 Silver, largest on a number 1 Gold (1000 Silver), largest on another spot 10 Gold (10 000 Silver). A GM may set 1 Silver to 1,000 Gold (1 000 000 Silver), and the smallest bet may not exceed either largest.
- Chips: 10, 50, 100, 500 Silver, 1 Gold, 5 Gold.
- The table starts closed. Missing setting rows mean closed with the starting limits. Nobody bets while it is closed, GMs included.
- The game calls the coins Gold, Silver and Bronze in everything a person reads. Code and columns keep `copper` / `dwCooper`.
- UI copy is plain ASCII punctuation, sentence case, no exclamation marks.
- Commits: `feat:` / `test:` / `docs:` prefix, ending with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`. Work on branch `feat/roulette`, never on `main`.

## Review Focus

1. **Spin pressed twice, or pressed again while the wheel turns:** one spin is sent, one stake is taken. (Task 6)
2. **A GM changes the limits while a player has chips down:** the spin is refused with the reason, nothing is taken, and the page shows the new limits. (Tasks 4 and 6)
3. **A wallet with loose Bronze, or one that changed in the game since the page loaded:** Bronze is kept exactly through a win and a loss; a stake the wallet no longer covers is refused and the page shows the real wallet. (Tasks 3 and 6)
4. **The character logs in after the page loaded:** the spin is refused naming the character, nothing is written, and the picker then shows it as in the game. (Tasks 3, 4 and 6)
5. **Setting rows hold something unreadable** (`roulette_min_bet = 'abc'`, a negative, a smallest bet above a largest): the table falls back to the starting limits instead of failing or accepting a nonsense bet. (Task 3)

Rules the signatures do not pin: `column1` is 1, 4, 7 … 34; `column2` is 2, 5 … 35; `column3` is 3, 6 … 36. `low` is 1 to 18. Zero is covered by `n0` only. `payout` is the sum over winning bets of `amount * (odds + 1)`. `numberHit` is true when a number bet won. `checkBets` messages, in this order of checking:

| Case | Message |
|---|---|
| no bets | `Put a chip on the table first` |
| a spot not in `ROULETTE_SPOTS` | `That is not a spot on the table` |
| a spot twice | `Each spot can only be bet on once` |
| amount not a whole number, or under `minBet` | `The smallest bet is ${silverText(minBet)}` |
| a number over `maxNumber` | `The largest bet on a number is ${silverText(maxNumber)}` |
| another spot over `maxOutside` | `The largest bet on ${spotLabel(spot)} is ${silverText(maxOutside)}` |

- [ ] **Step 2: Implement `walletBetSql`** with exactly this shape (the order of locks is the point; table names come from `tables`):

```sql
SET NOCOUNT ON; SET XACT_ABORT ON;
DECLARE @code INT = 0, @id INT = 0, @wallet BIGINT, @name VARCHAR(50), @online INT;
BEGIN TRAN;
IF NOT EXISTS (SELECT 1 FROM {portalSettings} WHERE szKey = '{liveKey}' AND szValue = 'true') SET @code = 1;
IF @code = 0
BEGIN
  -- A range lock on the account's rows in the online list: its login and enter-server wait for the COMMIT.
  SELECT @online = COUNT(CASE WHEN dwCharID = @charId THEN 1 END)
  FROM {currentUsers} WITH (UPDLOCK, HOLDLOCK) WHERE dwUserID = @userId;
  SELECT @name = szNAME, @wallet = CAST(dwGold AS BIGINT) * 1000000 + CAST(dwSilver AS BIGINT) * 1000 + dwCooper
  FROM {characters} WITH (UPDLOCK, ROWLOCK) WHERE dwCharID = @charId AND dwUserID = @userId AND bDelete = 0;
  IF @name IS NULL SET @code = 2;
  ELSE IF @online > 0 SET @code = 3;
  ELSE IF @wallet < @stake SET @code = 4;
END
IF @code = 0
BEGIN
  SET @wallet = @wallet - @stake + @payout;
  UPDATE {characters} SET dwGold = @wallet / 1000000, dwSilver = (@wallet / 1000) % 1000, dwCooper = @wallet % 1000 WHERE dwCharID = @charId;
  {record};
  SET @id = SCOPE_IDENTITY();
END
COMMIT;
SELECT @code AS code, @id AS id, @name AS name,
       CAST(@wallet / 1000000 AS INT) AS gold, CAST((@wallet / 1000) % 1000 AS INT) AS silver, CAST(@wallet % 1000 AS INT) AS copper;
```

`walletCharactersSql` selects from `{characters}` where `dwUserID = @userId AND bDelete = 0`, with `online` computed the way `findLevelFreeze` in `apps/api/src/characters/characters.repository.ts` does.

```ts
export type RouletteSettings = RouletteLimits & { live: boolean };
export type WalletCharacterRow = { charId: number; name: string; level: number; classCode: number; gold: number; silver: number; copper: number; online: boolean };
/** Money in Silver. */
export type RouletteSpinRow = { id: number; userId: number; character: string; spunAt: Date; pocket: number; stake: number; payout: number };
/** Money in Silver; the repository multiplies by 1000 for the database. */
export type BetInput = { userId: number; charId: number; pocket: number; stake: number; payout: number; bets: string; numberHit: boolean };
export type BetOutcome = { code: typeof BET_OK; id: number; wallet: Wallet } | { code: Exclude<BetCode, typeof BET_OK>; name: string | null };
export type RouletteTotalsRow = { spins: number; staked: number; paid: number };

export interface RouletteRepository {
  /** Closed with the starting limits when rows are missing or unreadable. */
  settings(): Promise<RouletteSettings>;
  saveSettings(settings: RouletteSettings, changedBy: string): Promise<void>;
  characters(userId: number): Promise<WalletCharacterRow[]>;
  bet(input: BetInput): Promise<BetOutcome>;
  spinsOf(userId: number, limit: number): Promise<RouletteSpinRow[]>;   // newest first
  bigWins(limit: number): Promise<RouletteSpinRow[]>;                   // bNumberHit = 1, newest first
  latest(limit: number): Promise<RouletteSpinRow[]>;                    // anyone, newest first
  totals(): Promise<{ today: RouletteTotalsRow; allTime: RouletteTotalsRow }>;  // today by the database's own date
}
export const ROULETTE_REPOSITORY = Symbol('ROULETTE_REPOSITORY');
export const ROULETTE_LIVE_KEY = 'roulette_live';
export class SqlRouletteRepository implements RouletteRepository { withTransaction(tx: sql.Transaction): SqlRouletteRepository; ... }
```

Settings keys in `TPORTALSETTING`: `roulette_live` (`'true'`/`'false'`), `roulette_min_bet`, `roulette_max_number`, `roulette_max_outside` (whole Silver as text). `settings()` reads all four in one query. A limit that is not a whole number from 1 to `ROULETTE_MAX_LIMIT` falls back to its starting value, and if the smallest bet then exceeds either largest, all three fall back. `saveSettings` writes the four rows with the `MERGE ... WITH (HOLDLOCK)` that `SqlWheelRepository.setLive` uses. Follow `SqlWheelRepository` for `withTransaction` and `request()`.
